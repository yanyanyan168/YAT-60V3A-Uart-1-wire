## 2. 已废弃的旧描述

以下旧总结不再正确，后续不能照做：

```text
1. CH_REPAIR 已补 val.curr <30mA 连续 3 秒有压无流。
2. CH_REPAIR 使用 set_Curr_Duty(SET_CURR(iREPAIR))。
3. CH_REPAIR 是普通 PWM 小电流修复。
4. vPRE_30V 没有依据、应从逻辑中删除。
5. vCH60 可直接用总压判断恢复。
6. DUMMY_LOAD 可作为某状态固定动作。
```

废弃原因：

```text
CH_REPAIR 走 REPAIR_OUTPUT 独立硬件修复通路。
REPAIR_OUTPUT 打开后硬件自动限流约 100mA。
CH_REPAIR 不经过 JK1 继电器，不需要 PWM 恒流设置。
DUMMY_LOAD 只在负载突然断开时打开 5 秒。
vPRE_30V 对应 2.0V*N，是硬件修复到主预充的边界。
vCH60 只是 4.0V*N 总压值，规格要求最高单节电压小于 4.0±0.05V。
```

## 3. CH_REPAIR 最新正确语义

```text
状态：CH_REPAIR
区间：1.0*N ~ 2.0*N
通路：REPAIR_OUTPUT 独立硬件修复支路
电流：硬件自动限流约 100mA
继电器：JK1 不闭合
PWM：主 PWM 输出关闭
禁止：set_Curr_Duty(SET_CURR(iREPAIR))
离开状态：必须关闭 REPAIR_OUTPUT
```

如果要做 CH_REPAIR 无电流异常判断，必须先确认修复支路电流是否经过当前 `val.curr` 采样通路。没有确认前，不要用 `val.curr <30mA` 作为 CH_REPAIR 硬故障依据。

## 4. 充电逻辑最新分段

严格按参数表和 3.2 充电逻辑，结合硬件通路，应按以下语义实现：

```text
val.vout < vSTART：
    电压异常，关输出，红灯闪，绿灯灭，必须拔插恢复。

vSTART <= val.vout < vPRE_30V：
    CH_REPAIR，打开 REPAIR_OUTPUT，硬件 100mA 修复，不闭合 JK1，不开 PWM。

vPRE_30V <= val.vout < vPRE_37V5：
    CH_Pre1，闭合 JK1，iPRE=500mA 主预充。

val.vout > vPRE_37V5：
    CH_CCCV / CC，大电流充电。

val.vout 达到 4.20*N 且电流降到 iGED：
    CH_FULL，完全切断充电，红灭绿常亮。
```

## 5. DUMMY_LOAD 最新正确语义

```text
DUMMY_LOAD 默认关闭。
只在负载突然断开时打开。
打开保持 5 秒。
5 秒后自动关闭。
不能在 CH_REPAIR / CH_Pre1 / CH_CCCV / CH_FULL 中固定常开。
```

后续源码需要补齐：

```text
突然断开触发条件
DUMMY_LOAD = 1
5 秒计时
DUMMY_LOAD = 0
```
