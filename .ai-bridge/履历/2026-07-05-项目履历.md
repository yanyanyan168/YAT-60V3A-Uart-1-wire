## 3. 充电器规格关键信息

来源：`63V 3A 充电器规格.pdf`

### 输入特性

```text
输入电压范围：AC90-138Vac
输入频率：47~63Hz
空载最大功耗：<1W
效率：>85%
浪涌电流：<50A @138Vac
```

### 输出特性

```text
最高输出电压：64.3±0.5V
额定待机电压：35V±0.5V
额定输出电流：3±0.3A
充满截止电压/电流：63V±0.20V，500±200mA
滞后恢复充电电压：最高单节电压小于 4.0±0.05V
匹配电池包：63V battery pack
输出纹波和噪声：≤220mVp-p
```

### 修复/涓流/预充

规格书里有两段低压充电描述：

```text
涓流：电池电压在涓流范围内，不开继电器，以 100mA 以下充电，时间 30min±5%。
预充：电池电压在 1.0~2.5V/节范围内，以 500±200mA 充电，时间 30min±5%。
```

当前源码对应理解：

```text
CH_REPAIR：低压修复，小电流 iREPAIR，继电器断开，只开修复输出。
CH_Pre1：预充，继电器闭合，按 iPRE 输出。
CH_CCCV：正常 CC/CV 充电。
```

### 保护与恢复

```text
低压保护：电池包电压低于 1.0±0.2*N V 时关断输出并报错。
过流保护：充电电流超过 3.5±0.3A 时关断输出并报错。
过压保护：电池电压超过 4.2±0.02*N V 时关断输出并显示充满。
短路保护：输出短路时充电器不能损坏。
温度保护：21700 超过 57±3℃或低于 -2±3℃停止充电；18650 超过 50±3℃或低于 -2±3℃停止充电。
通信异常保护：电池包插入时通信异常，切断输出。
定时关断保护：容量/电流*60min*1.25 + 30min。
保护动作时：不得有输出电压和电流，即完全关闭。
```

### LED 状态

```text
无电池/待机：红灯常亮，绿灯灭。
充电中：红灯灭，绿灯 1Hz 闪烁。
电压异常：红灯 1Hz 闪烁，绿灯灭。
温度异常：红绿灯 1Hz 交替闪烁。
充满：红灯灭，绿灯常亮。
```

### 端口定义

```text
Port 1：B+
Port 2：Charge positive C+
Port 3：COM
Port 4：Charge negative B-
```

### 充电逻辑摘要

```text
上电无电池：红灯常亮，绿灯灭。
电池插入：通过电压判断是否插入。
低于 1*N V：关断输出，红灯闪烁。
1*N ~ 2.5*N V：预充电流充电，30min 未达到 2.5*N V 以上进入异常。
大于 2.5*N V：进入大电流 CC 充电。
达到 4.20*N V 后逐渐减少充电电流。
电流降到关断电流时：指示充满，完全切断充电。
温度异常恢复后可自动重新开始。
电流/电压/通信异常后，需要重新插拔电池再运行。
```

## 4. 一线/BMS 通信协议关键信息

来源：`60V 3A 通信协议.pdf`、`X6_BMS_Communication_Protocol_V1.3_FullContent.html`

### 通信基本要求

```text
单总线，主从模式，可变波特率，默认 4800bps。
1 位停止位，无奇偶校验。
初始通讯时，充电器/工具为主机，电池包为从机。
主机主动发送命令，从机被动回复。
TTL 电平，主机提供上拉，从机开漏输出。
高电平 > 0.8*Vdd，低电平 < 0.2*Vdd。
从机上电后 50ms 内准备接收。
主机发送后，从机 10ms 内回复，通常停止位后 0.2~5ms 内回复。
主机收到回复后，最快间隔 6ms 发送下一条。
未收到回复时，主机继续发送 10 次。
从机收到通讯中断超过 2s 后判断通信故障。
总线持续低电平 >30ms，判断断开主机。
```

### 硬件接口

```text
主机上拉电阻：10K。
从机提供下拉电阻，供主机识别是否有从机。
COM1 / COM4 为总线对外接口。
```

### 帧格式

```text
主机发送：CMD + DATA... + CHK
从机回复：CMD + DATA... + CHK
非 PDU 协议校验：CHK = CMD + DATA1 + ... + DATAN
电池包通讯：大端模式
PDU 通讯：小端模式
```

### 振荡模式

```text
正常：10ms 低 + 10ms 高
电压异常：10ms 低 + 20ms 高
温度异常：10ms 低 + 30ms 高
电流异常：10ms 低 + 40ms 高
```

当前工程主要使用数据通信，不要随意改一线业务收发逻辑。

## 5. 当前已使用/关注的协议命令

### 查询配置

```text
A0：查询从机配置/电池包识别码/串并数
A1：查询电芯规格、容量
A4：查询电芯充电单节电压范围，含预充截止电压和过充电压
A6：查询电芯最大充放电电流
A7：查询二级充电温度、电流范围
```

### 查询状态

```text
B1：查询单节最低/最高电压
B3：查询电池包温度和充电 MOS 温度
B4：查询电池包充电状态信息
B6：控制电池包 LED / MOS / 蜂鸣器 / 显示电量
```

### B4 状态位

```text
b0：单节过充
b1：充电低温
b2：充电高温
b3：充电 MOS 过温
b4：过流
b5：短路
b6：充电超时
b7：电池包失效
```

### 充电通信流程

协议文档中的充电器流程：

```text
1. 发送 A0 查询从机配置。
2. 发送 A1 查询电芯容量，设定最长充电保护时间。
3. 发送 A4 查询预充电压、充满电压。
4. 发送 A6 查询最大充电电流。
5. 发送 A7 查询二级充电温度/电流。
6. 发送 B1 查询单节最低/最高电压。
7. 发送 B3 查询电池包温度、充电 MOS 温度。
8. 发送 B4 查询电池包状态。
9. 发送 B6 让电池包显示状态或执行动作。
10. 充电中重复 6~9。
11. 充满后发送电池包显示电量数据，3 分钟后停止发送。
12. 充电器检测 BT+ 端口判断电池包是否拔除，恢复待机。
```

## 6. 当前源码充电状态履历

### CH_IDLE

```text
输出关闭。
BATT_DIVIDER_EN = 1。
实时看电池是否接入。
val.vout >= vSTART 连续 500ms 后进入 BMS_HANDSHAKE。
vRESET < val.vout < vSTART 稳定 2 秒后进入 CH_UVP。
```

### BMS_HANDSHAKE

```text
输出关闭。
BATT_DIVIDER_EN = 1。
等待 A0/A1/A4/A6/A7/B1/B3/B4 等信息。
握手最多等待 20 秒，超时进入 BMS_ERR。
```

### CH_Check

```text
输出关闭。
BATT_DIVIDER_EN = 1。
根据电池电压和 BMS 状态决定进入 CH_REPAIR / CH_Pre1 / CH_CCCV。
不做无电流检查，因为该状态还没有实际输出。
```

### CH_REPAIR

```text
低压修复。
BATT_DIVIDER_EN = 1。
继电器断开，只开修复小电流 iREPAIR。
达到 vPRE_30V 后转 CH_Pre1。
已补有压无流检查：val.curr < 30mA 连续 3 秒进入 HW_ERR。
```

### CH_Pre1

```text
预充。
BATT_DIVIDER_EN = 1。
继电器闭合，按 iPRE 输出。
实际按 iPRE 做有压无流判断，避免协议目标电流偏小漏判。
val.curr < 100mA 连续 3 秒进入 HW_ERR。
预充达到预充截止电压后转 CH_CCCV。
```

### CH_CCCV

```text
正常 CC/CV 充电。
BATT_DIVIDER_EN = 1。
继电器闭合，按协议目标电流和 CCCV 降额逻辑输出。
val.curr < 100mA 连续 3 秒进入 HW_ERR。
接近目标电压 500mV 内不判有压无流，避免误判满电末端。
达到目标电压且电流 <= iGED 连续 1 秒后进入 CH_FULL。
```

### CH_FULL

```text
输出关闭。
分压默认关闭。
每 1 秒短开一次分压，20ms 后 ADC 有效，最多打开 100ms。
val.vout < vRESET 连续 2 次有效采样后回 CH_IDLE。
val.vout < vCH60 连续 2 次有效采样后重新握手。
协议显示满电后约 3 分钟停止通信并拉低 COM。
```

### 异常/保护状态

```text
BMS_TEMP_ERR
BMS_ERR
CH_OTP
CH_TimOut
CCCV_TimOut
CH_UVP
CH_OVP
CH_OCP
NTC_ERR
HW_ERR
```

这些状态一般输出关闭，分压默认关闭，周期短开检测电池端电压；拔电池后回待机。温度异常恢复后可重新握手，电流/电压/通信异常通常要求重新插拔。

## 7. 拔电池逻辑履历

### 充电中拔电池

当前 `CH_Pre1` / `CH_CCCV` 中直接处理。

逻辑：

```text
val.curr < iGED 且 u1w_info.no_rx_10ms >= 100U
    -> 疑似充电中拔电池
    -> ch_output_all_off()
    -> BATT_DIVIDER_EN = 1
    -> 20ms 后用当前 ADC 换算后的 val.vout 判断
```

结果：

```text
val.vout < vRESET：正常拔电池，回 CH_IDLE，日志“拔电池”。
val.vout >= vRESET：异常拔出，进 BMS_ERR，日志“拔出异常”。
```

重要注意：继电器闭合时不能直接用 `val.vout` 判拔电池，因为可能是充电器输出电压。必须先关输出，再短等，再看电池端电压。

### 满电/异常状态拔电池

只在短开分压并且 ADC 有效时判断：

```text
val.vout < vRESET 连续 2 次有效采样 -> CH_IDLE
```

## 10. Flash / 空间履历

关键规则：不能只看 Keil `code`，要保留校准区。

```text
程序区：0x0000 ~ 0x3F7F = 16256 bytes
校准区：0x3F80 ~ 0x3FFF = 128 bytes，不可占用
```

计算时保守看：

```text
code + const <= 16256
```

或者看整片 16K 时：

```text
code + const + 128 <= 16384
```

当前最近编译：

```text
0 Error(s), 0 Warning(s)
Program Size: data=157.3 xdata=315 const=146 code=15635
```

保守剩余：

```text
16256 - (15635 + 146) = 475 bytes
```

结论：空间很紧，后续只能小修。不要新增大日志、大表、大字符串、大函数。

## 11. 编码履历

### 当前规则

```text
ch.c 等旧 MCU 源码：GBK / CP936，无 BOM，CRLF。
uart_1_wire_debug.c/h：UTF-8 无 BOM。
memory.md：UTF-8-BOM。
.ai-bridge 新 Markdown：UTF-8，可用中文。
```

### 重要坑

Keil C51 的 C/H 文件不能加 UTF-8-BOM，否则可能报 unprintable character 0xEF/0xBB/0xBF。

CodexPro.read 显示中文 mojibake，不一定代表源码真乱码。要看文件实际编码和 Keil 编译结果。

某些工具修改 `ch.c` 会把文件转成 UTF-8；若发生这种情况，不能直接从含替代字符的 UTF-8 转回 GBK。正确做法是从 git 恢复 GBK 版本，再用 GBK 脚本重新打补丁。
